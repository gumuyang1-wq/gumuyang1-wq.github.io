时间范围筛选和日期口径

掌握完整月份、活动周期这类时间范围写法。

本节讲解

先放进产品场景里理解

假设你在看一个产品数据需求：统计 2026 年 7 月内已支付订单的金额总和。这节课的重点不是把 SQL 背下来，而是能判断这句 SQL 解决了哪个业务问题、还缺哪些口径确认。

学完后你应该能做到两件事：第一，掌握完整月份、活动周期这类时间范围写法；第二，看到类似 SQL 时能主动追问：这个时间范围是自然月、最近 30 天，还是活动周期？

核心概念

筛完整 7 月，常用 paid_at >= '2026-07-01' AND paid_at < '2026-08-01'。上限用小于下个月第一天，能覆盖 7 月 31 日所有时分秒。

SELECT SUM(amount)
FROM orders
WHERE status = 'paid'
  AND paid_at >= '2026-07-01'
  AND paid_at < '2026-08-01';

统计 2026 年 7 月内已支付订单的金额总和。

SQL 逐行拆解
SELECT SUM(amount)

先确定要看哪些字段，或者要算哪个指标。产品读 SQL 时先问：这里输出的是明细、人数、次数，还是金额。

FROM orders

确定数据来自哪张表。表的粒度很关键，一行是一笔订单、一个用户，还是一次行为，会直接影响结果。

WHERE status = 'paid'

在计算前先筛明细数据。这里决定哪些记录有资格进入统计，最容易影响指标口径。

AND paid_at >= '2026-07-01'

继续收紧筛选范围。每多一个条件，都要问它是业务定义的一部分，还是临时分析限制。

AND paid_at < '2026-08-01';

继续收紧筛选范围。每多一个条件，都要问它是业务定义的一部分，还是临时分析限制。

常见坑

这一节最容易错在这里

只看日期字面值，不问时间字段是否带时分秒，也不问指标应该按创建时间、支付时间还是退款时间归属。

题目材料

SELECT SUM(amount)
FROM orders

  AND paid_at >= '2026-07-01'

练习 1：拆成 3 句话

请按 3 句话回答：1. 这句 SQL 从哪张表拿数据；2. 先筛掉了哪些数据；3. 最后输出的业务结果是什么。

练习 2：改错或找风险

改错题：如果有人把 7 月写成 paid_at <= '2026-07-31'，或写成 BETWEEN '2026-07-01' AND '2026-07-31'，请指出它可能漏掉哪段数据，并写出更稳的时间范围。

练习 3：补 3 个口径问题

假设你要把这个结果发给研发或数据同学确认，请写出 3 个你会追问的问题，重点问字段含义、时间口径、状态口径或是否去重。

卡住时怎么做

不会不是失败，按这个顺序处理

  1. 先回到“题目材料”，圈出表名、筛选条件、输出指标。
  2. 只打开当前这一题的参考答案，别一次把三题全看完。
  3. 看完后合上答案，用自己的话再说一遍。
  4. 如果还是不懂，先不要点完成，把卡点记成一句问题，回聊天里问我。
